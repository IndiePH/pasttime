# Reversi Hotseat Implementation Plan

> **Status:** The tasks below shipped the playable Reversi board. The play screen calls `createComputerSession`, `chooseMove`, and `applyComputerMove`. Settings store Easy, Medium, or Hard and Animate Flips, which starts on. Play uses `GamePlaySection`. Completed-match stats and the terminal result dialog are also shipped. The current rules are `docs/superpowers/specs/2026-11-05-reversi-design.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a finishable 8×8 Reversi match where one person plays Black against a local computer, with human and computer moves on separate functions, completed-match stats, and a noticeable terminal result dialog.

**Architecture:** `Position` in `packages/domain/games/reversi/` owns the board, turn, pass, and result. `Session` adds a human or computer seat per color. The web play view uses a human Black seat and a local computer White seat. Completed matches are stored separately from daily engagement records and reduced into Reversi stats.

**Tech Stack:** TypeScript, Vitest, React, Next.js, Testing Library.

## Global Constraints

- The first slice seated both colors as human. The shipped page seats Black as human and White as a computer. Easy, Medium, and Hard are stored on the device. There is still no save, stats, streak, share card, or room.
- Starting center, top-left of those four squares first: White, Black, Black, White. Black moves first. Row `0` is rank 8.
- A click places a disc only through `acceptHumanMove`. When the seat to move is the computer, the page calls `chooseMove` and `applyComputerMove`.
- Hub label is `1 player`. Tags are `board` and `strategy`. No `multiplayer` tag, `minPlayers`, or `maxPlayers`.
- Action labels: `Play`, `New Game`, `How To Play`.
- Do not commit unless the user asks.
